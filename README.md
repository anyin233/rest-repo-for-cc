# 分布式调度系统建模

这个项目实现了一个分布式任务调度系统的仿真，比较了三种不同的调度算法在四峰分布工作负载下的性能。

项目提供两种实现：
1. **简化版本** (`scheduler.py`): 基础实现，用于快速理解调度算法
2. **真实版本** (`realistic_scheduler.py`): 真实模拟实际场景，包含动态队列更新和基于分位数的分布表示

## 系统模型

### 系统架构
- **n个节点**：分布式系统由n个工作节点组成
- **相同模型**：每个节点执行相同的任务处理模型
- **随机执行时间**：对于输入x，执行时间f(x)服从某个概率分布
- **真实并发**：每个节点必须完成当前任务才能处理下一个任务

### 调度算法

#### 1. Round Robin (轮询调度)
- **原理**：按顺序将任务依次分配到各个节点的任务队列
- **优点**：实现简单，保证负载均衡
- **缺点**：不考虑任务执行时间差异，可能导致某些队列堆积

#### 2. Shortest Queue (最短队列)
- **原理**：计算每个队列的总执行时间期望和方差，选择综合得分最低的队列
- **评分公式**：`score = E[T] + α * σ[T]`
  - E[T]：队列总时间期望
  - σ[T]：队列总时间标准差
  - α：方差权重参数（默认0.5）
- **动态更新**：
  - 任务到达时：`E[T] += E[T_new]`, `Var[T] += Var[T_new]`
  - 任务完成时：`E[T] -= E[T_completed]`, `Var[T] -= Var[T_completed]`
- **优点**：考虑任务差异，更智能的负载均衡
- **缺点**：需要计算期望和方差，计算开销稍大

#### 3. Probabilistic (概率采样)
- **原理**：使用分位数表示队列总时间的分布，通过采样选择最优队列
- **分位数表示**：`[P5, P10, P25, P50, P75, P90, P95]`
- **分布运算**：
  - **加法**（任务到达）：`Q_new(p) = Q_queue(p) + Q_task(p)`
  - **减法**（任务完成）：`Q_new(p) = Q_queue(p) - Q_task(p)`
- **调度决策**：从每个队列的分位数分布中采样，选择采样值最小的队列
- **优点**：保留完整的分布信息，不仅仅是期望值
- **缺点**：需要维护分位数数组

## 数据集

### 四峰分布
使用高斯混合模型生成四峰分布，模拟真实系统中不同类型任务的执行时间分布：

| 峰编号 | 中位数 | 标准差 | 权重 |
|--------|--------|--------|------|
| 峰1    | 50秒   | 10秒   | 25%  |
| 峰2    | 100秒  | 15秒   | 25%  |
| 峰3    | 175秒  | 20秒   | 25%  |
| 峰4    | 375秒  | 40秒   | 25%  |

这种分布模拟了：
- **短任务**（峰1）：快速查询、简单计算
- **中等任务**（峰2-3）：标准数据处理
- **长任务**（峰4）：复杂分析、批处理

## 核心特性

### 真实调度模拟 (`realistic_scheduler.py`)

1. **基于分位数的分布表示**
   - 使用7个分位数点 `[P5, P10, P25, P50, P75, P90, P95]` 表示执行时间分布
   - 支持分布的加法和减法运算
   - 从正态分布自动生成分位数

2. **动态队列状态更新**
   - 任务到达时：将任务的分布添加到队列分布
   - 任务完成时：从队列分布中减去任务的分布
   - 实时维护队列的期望、方差和分位数

3. **真实事件驱动仿真**
   - 任务到达事件
   - 任务开始执行事件
   - 任务完成事件
   - 节点必须完成当前任务才能处理下一个

## 实验结果

### 真实调度器结果（推荐参考）

基于1000个任务、4个节点、0.5任务/秒到达率的实验：

| 指标 | Round Robin | Shortest Queue | Probabilistic |
|------|-------------|----------------|---------------|
| 平均响应时间 | 20337.69s | 20304.12s | **20302.20s** |
| 中位数响应时间 | 20433.77s | 20283.24s | **20245.02s** |
| P95响应时间 | 38409.31s | **38156.09s** | 38253.61s |
| P99响应时间 | 40627.87s | **39871.23s** | 39963.50s |
| 最大响应时间 | 41420.02s | **40616.14s** | 40700.01s |

### 主要发现

1. **Probabilistic调度器**在平均响应时间和中位数响应时间上表现最佳
   - 基于分位数的完整分布信息使得调度决策更准确

2. **Shortest Queue调度器**在高分位数（P95/P99）和最大响应时间上表现最佳
   - 考虑方差使得长尾延迟更低

3. 三种算法的性能差异约为0.1-0.9%
   - 在该工作负载下，算法选择影响相对较小
   - 但在高负载或异构环境下差异可能更显著

4. **动态队列更新机制**的重要性
   - 任务完成时及时更新队列状态
   - 使调度器始终基于最新的队列信息做决策

## 技术特点

### 高效实现
1. **离散事件仿真**：使用优先队列（heapq）实现高效的事件调度
2. **O(1)队列选择**：
   - Round Robin：常数时间
   - Shortest Queue：O(n)，n为节点数
   - Probabilistic：O(n)，n为节点数
3. **内存优化**：增量更新队列统计信息，避免重复计算

### 分布运算（真实版核心特性）

#### 分位数加法
当任务到达并加入队列时：
```python
Q_new(p) = Q_queue(p) + Q_task(p)
```
- 近似独立随机变量和的分位数
- 实际应用中效果良好

#### 分位数减法
当任务完成并离开队列时：
```python
Q_new(p) = Q_queue(p) - Q_task(p)
```
- 从队列分布中移除任务的分布
- 保持队列状态的一致性

#### 期望和方差更新
```python
# 加法
E[Total] = E[Queue] + E[Task]
Var[Total] = Var[Queue] + Var[Task]  # 假设独立

# 减法
E[Total] = E[Queue] - E[Task]
Var[Total] = max(Var[Queue] - Var[Task], 0)
```

### 可扩展性
- 支持自定义调度算法
- 参数化的仿真器配置
- 模块化设计，易于扩展
- 支持自定义任务执行时间分布
